# 鸿蒙设备端 ⇄ 电脑端 视频流协议 (v1)

设备端 App（`harmony/`，包名 `com.qtscrcpy.streamer`）在手机上监听回环地址 `tcp:27183`。
电脑端用 `hdc -t <设备> fport tcp:<本机端口> tcp:27183` 转发，再连接本机端口。

所有整数均为**大端序**。

## 选择来源并启动

电脑端通过 hdc 启动 App 并带上来源参数：

```
hdc -t <设备> shell aa start -a EntryAbility -b com.qtscrcpy.streamer --ps source <screen|back|front>
```

App 在前台启动后开始监听（屏幕来源会弹出系统的录屏授权，摄像头来源需要相机权限，均需要用户在手机上点一次“允许”）。
电脑端应重试连接，直到握手成功或超时。更换来源时电脑端须先让 App 退出
(`hdc shell aa force-stop com.qtscrcpy.streamer`) 再重新启动。

## 握手

连接建立后，设备端先发一个 16 字节的头（电脑端不需要发送任何数据）：

| 偏移 | 大小 | 内容 |
| ---- | ---- | ---- |
| 0 | 4 | 魔数 `QSC1` (0x51 0x53 0x43 0x31) |
| 4 | 1 | 来源：`0` 屏幕，`1` 后置摄像头，`2` 前置摄像头 |
| 5 | 1 | 编码：`0` H.264 (Annex B) |
| 6 | 2 | 保留，置 0 |
| 8 | 4 | 视频宽度（像素） |
| 12 | 4 | 视频高度（像素） |

## 数据包

握手之后，设备端持续发送数据包，每个包：

| 偏移 | 大小 | 内容 |
| ---- | ---- | ---- |
| 0 | 1 | 类型：`0` 配置（SPS/PPS），`1` 关键帧，`2` 普通帧 |
| 1 | 3 | 保留，置 0 |
| 4 | 8 | 时间戳（微秒，设备单调时钟） |
| 12 | 4 | 负载长度 N（不超过 8 MiB，否则视为协议错误） |
| 16 | N | 负载：H.264 Annex B 码流（带 `00 00 00 01` 起始码） |

- 配置包的负载是 SPS+PPS。电脑端应缓存，并在每个关键帧前重新送入解码器。
- 设备端每 1 秒强制出一个关键帧，所以电脑端丢帧或解码出错后最多 1 秒恢复；v1 没有“请求关键帧”的反向通道。
- 屏幕画面静止时设备端可能长时间不发包，这是正常的，电脑端不得把“没有包”当作错误。
- 分辨率可能在流中变化（旋转屏幕）：新的配置包携带新的 SPS，电脑端以解码出的帧尺寸为准。

## 关闭

任意一方关闭 TCP 连接即结束。电脑端读取失败时应提示并停止，不要自动无限重连。
